## 제품 한 줄 정의

10m 이내 초근접 거리 기반 익명 채팅과 목적형 오프라인 셔플챗을 결합한 하이브리드 소셜 앱.
(MVP 범위 = 오프라인 이벤트 기반 셔플챗만. BLE 근접 탐색은 Phase 2.)

## 핵심 철학 (절대 안 바뀌는 원칙)

1. **외모/스펙이 아닌 취향·대화 중심 매칭**
   프로필 사진, 실명은 앱 내 어디에도 노출하지 않는다. 매칭과 대화는 텍스트로만 이루어진다.

2. **시공간 제한이 주는 긴장감과 희소성**
   라운드 시간(기본 10분), 이벤트 참가라는 물리적 제약 자체가 재미의 핵심이다. 이 제약을 없애거나 느슨하게 만드는 제안(예: 무제한 채팅, 상시 매칭)은 방향 위반이다.

3. **어장(Fishbowl) = 지속 관계 관리 체계**
   라운드가 끝나도 관계가 끊기지 않고, 상호 선택된 사람만 영구 채팅방으로 이어진다는 것이 리텐션의 핵심 장치다.

4. **디자인: Stealth & Utility**
   - 핑크/퍼플 등 데이팅 앱 특유의 화려한 색상 금지.
   - 흰 배경 + 무채색(검정/회색) 텍스트, 시스템 폰트, 카카오톡/문자앱처럼 심심하게.
   - 긴장감은 디자인이 아니라 "1분 전 경고 타이머", "어장 선택 팝업" 같은 **기능적 UI**에서만 나온다.
   - 새 색상/톤을 추가하고 싶다면 이 원칙 위반 여부를 먼저 검토한다.

5. **텍스트 전용 (안전장치)**
   이미지, 동영상, 음성, 이모티콘 전송은 금지한다. 신원 노출/악용 리스크를 줄이기 위한 의도적 제약이며, 편의 기능이라는 이유로 완화하지 않는다.

6. **신고/차단은 선택이 아니라 필수 인프라**
   매칭 기능을 확장할 때마다 "신고된/차단된 유저는 제외되는가"를 함께 검토한다.

## 현재 단계

**Phase 1 (MVP)** — 일산 오프라인 테스트용 4:4 셔플챗 코어 로직 구현.
순수 타이머 기반 랜덤 로테이션 매칭으로 먼저 검증한다. 결과 해석 시
"취향 매칭 없이도 통하는가"와 "취향 매칭이 있었다면 더 나았을까"를
구분해서 본다 (Phase 1.5 검토 근거, 아래 참고).

**Phase 1.5 (검토 예정, MVP 결과 확인 후 결정)**
- 최소 설문/관심사 태그 기반 매칭 (PRD의 "Vibe Filter" 개념)
- 근거: 2026년 기준 데이팅 시장은 순수 로테이션형 스피드데이팅보다
  취미/관심사를 매개로 한 모임 쪽이 훨씬 빠르게 성장 중이다
  (트리비아 나이트 참석 +388%, 마작 모임 +235% 등, 2023→2024 기준).
  BLE(Phase 2)보다 구현 비용이 훨씬 낮으면서 이 트렌드에 더 가까워질
  수 있는 지점이라 Phase 2보다 먼저 검토한다.
- MVP 파일럿에서 "랜덤 매칭만으로 충분히 재밌는가"가 확인되면
  우선순위를 낮추고, 대화 품질/지속률이 아쉬웠다면 최우선으로 올린다.

**Out of Scope (Phase 2+)**
- BLE 기반 10m 근접 탐색
- 결제 시스템

## 기술 원칙

- 스택: React + TypeScript + Vite + Tailwind CSS + Firebase (Auth/Firestore)
- 모바일 웹 우선 (iOS Safari / Android Chrome 뷰포트 기준)
- 서버 로직이 필요한 것(권한, 매칭 확정 등)은 Firestore 보안 규칙 + 클라이언트 로직으로 우선 해결하고, 별도 백엔드 서버 신설은 방향 B 이후로 미룬다.
